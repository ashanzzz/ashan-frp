# Ashan FRP Wireframe / 线框图稿

> 适用范围：`ashan-frp` 管理台页面级线框图与资源抽屉草图。
> 目标：把 `form-layout-draft.md` 继续推进成真正可视化的页面骨架，方便后续做前端页面、抽屉组件、状态占位和交互验收。
> 当前状态说明：本文是 **目标线框稿**，不是当前仓库实现截图。
> 配套文档：`frontend-ui.md`、`form-layout-draft.md`、`backend-schema.md`、`frpc-runtime.md`。
> 配套可视文件：`wireframe-draft.excalidraw`（可直接拖到 Excalidraw 打开）。

---

## 1. 本稿覆盖范围

这份线框稿优先覆盖最关键、最容易影响后续组件结构的 4 类页面：

1. **节点列表 + 节点编辑抽屉**
2. **隧道列表 + 隧道编辑抽屉**
3. **网站映射列表 + 网站映射编辑抽屉**
4. **设置页卡片布局 + 固定保存条**

暂不单独画的页面：
- 仪表盘
- 任务队列详情
- 日志详情
- 登录页

这些页面仍然遵循 `frontend-ui.md` 的总布局规则，但不属于当前“表单落地”这条主线的第一批线框图。

---

## 2. 统一线框约定

### 2.1 页面骨架

所有资源页统一采用：

- 左侧侧边栏
- 顶部页面标题区
- 标题下方筛选条 / 操作条
- 主列表区
- 右侧抽屉（打开时）

### 2.2 颜色语义（仅供线框表达）

| 区域 | 线框语义 |
|---|---|
| 侧边栏 / 页面壳 | 导航与框架 |
| 黄色块 | 筛选条 / 页面头 / 操作带 |
| 紫色块 | 抽屉 / 复杂编辑区 |
| 绿色块 | 固定底部操作栏 |
| 红色块 | 危险操作区 |
| 蓝色 / 青色块 | 列表、只读摘要、预览区 |

### 2.3 交互标记

- `主按钮`：页面级主操作，如“新建节点”“新建隧道”
- `保存并排队`：保存后立即创建 job
- `只读摘要`：展示状态、远端 ID、最近错误，不允许编辑
- `折叠区`：高级字段默认收起

## 3. Frame A — 节点列表 + 节点抽屉

### 3.1 目标

该线框回答两个问题：

1. 节点列表页如何在“资源筛选”和“状态排障”之间平衡。
2. 节点抽屉如何做到“左边定义连接、右边看运行状态”。

### 3.2 ASCII 线框

```text
┌───────────────侧边栏──────────────┬──────────────────────── 页面头 ────────────────────────┬──────── 节点抽屉 / 720px ────────┐

│ - 仪表盘                          ├────────────────────────────────────────────────────────┤───────────────────────────────────┤
│ 资源                              │ 搜索 | provider | 状态 | 健康状态 | 归档 | 刷新         │ 基础接入          | 运行摘要(只读)  │
│ - 节点                            ├────────────────────────────────────────────────────────┤ - display_name    | health_status  │
│ - 隧道                            │ 状态 | 节点名 | provider | endpoint | 心跳 | 依赖 | 操作 │ - provider        | last_seen_at   │
│ - 网站映射                        │--------------------------------------------------------│ - node_type       | last_success   │
│ 运营                              │ 在线 | hk-main | chmlfrp | xxx | 2m前 | 6 | 查看/编辑     │ - endpoint_url    | last_error_msg │

│ - 日志                            │ 离线 | cf-edge | cf      | xxx | 1h前 | 2 | 查看/编辑     │ - status          |                │
│ 系统                              │ ...                                                    ├───────────────────────────────────┤
│ - 设置                            │                                                        │ 高级标识（折叠）                  │
│                                   │                                                        │ - canonical_name                  │
│                                   │                                                        │ - external_id(只读)               │
│                                   │                                                        │ - metadata_json                   │
│                                   │                                                        ├───────────────────────────────────┤
│                                   │                                                        │ [测试连接]       [取消][保存]     │
└───────────────────────────────────┴────────────────────────────────────────────────────────┴───────────────────────────────────┘
```

### 3.3 关键说明

- 左侧列表区重点看：状态、最近心跳、依赖数量。
- 抽屉第一屏不出现快照全文、审计全文。
- `测试连接` 不是主按钮，避免和保存混淆。
- `运行摘要` 必须始终只读，不能让用户把运行事实误当配置改掉。

## 4. Frame B — 隧道列表 + 隧道抽屉

### 4.1 目标

隧道页是最典型的“期望态 vs 运行态”页面，所以线框必须把：

- 定义区
- 预览 / 差异区
- 运行摘要区

同时放在一屏可理解的位置。

### 4.2 ASCII 线框

```text
┌───────────────侧边栏──────────────┬─────────────────────── 页面头 ───────────────────────┬──────── 隧道抽屉 / 960px ────────┐
│ 资源                              │ 隧道列表                           [新建隧道]         │ 标题：编辑隧道   状态Tag          │
│ - 节点                            ├───────────────────────────────────────────────────────┤───────────────────────────────────┤
│ - 隧道                            │ 搜索 | 节点 | 期望状态 | 差异状态 | 手动覆盖 | 刷新   │ 基础定义          | 运行摘要(只读)  │
│ - 网站映射                        ├───────────────────────────────────────────────────────┤ - node_id         | actual_state   │
│                                   │ 状态 | 隧道名 | 节点 | 本地地址 | 远端端口/域名 | 操作 │ - name            | state_reason   │
│                                   │-------------------------------------------------------│ - tunnel_type     | last_applied   │
│                                   │ 正常 | mc-web | hk-main | 127.0.0.1:25565 | 6001   │ - desired_state   | last_error_msg │
│                                   │ 差异 | npm    | sg-aio  | 127.0.0.1:3000  | a.com  ├───────────────────────────────────┤
│                                   │ 失败 | api    | cf-edge | 127.0.0.1:8080  | 7001   │ 本地目标          | 预览 / 差异     │
│                                   │ ...                                                   │ - local_ip        | canonical_key  │
│                                   │                                                       │ - local_port      | 域名/端口预览  │
│                                   │                                                       ├───────────────────────────────────┤
│                                   │                                                       │ 远端暴露          |                │
│                                   │                                                       │ - remote_port     | desired vs obs │
│                                   │                                                       │ - dns_domain      | 手动覆盖提示   │
│                                   │                                                       │ - dns_proxied     |                │
│                                   │                                                       ├───────────────────────────────────┤
│                                   │                                                       │ 高级区（折叠）                     │
│                                   │                                                       │ - external_id(只读)               │
│                                   │                                                       │ - manual_override 摘要            │
│                                   │                                                       │ - runtime_key(只读)               │

```

### 4.3 关键说明

- 列表区必须让用户一眼看到“正常 / 差异 / 失败”。
- 抽屉右上区域必须保留 `运行摘要`，否则用户保存前不知道自己是在修定义还是修漂移。
- `保存并排队应用` 是该页最重要动作，应该是主按钮。
- `查看差异`、`复制`、`归档` 建议进入更多菜单，不占底部主操作位。

## 5. Frame C — 网站映射列表 + 网站映射抽屉

### 5.1 目标

网站映射是当前设计里最复杂的业务对象，线框重点不是“多字段”，而是把复杂度压成四层：

1. 基础绑定
2. HTTPS / 证书
3. 代理与缓存
4. 同步摘要 / 高级覆盖

### 5.2 ASCII 线框

```text
┌───────────────侧边栏──────────────┬────────────────────── 页面头 ────────────────────────┬──── 网站映射抽屉 / 960px~全屏 ────┐
│ 资源                              │ 网站映射                           [新建映射]         │ 标题：编辑映射   状态Tag          │
│ - 节点                            ├───────────────────────────────────────────────────────┤───────────────────────────────────┤
│ - 隧道                            │ 域名搜索 | 节点 | HTTPS | 同步状态 | 归档 | 刷新      │ 基础绑定          | 同步摘要(只读)  │
│ - 网站映射                        ├───────────────────────────────────────────────────────┤ - source_kind     | status         │
│                                   │ 状态 | 主域名 | 绑定节点 | 绑定隧道 | HTTPS | 同步 | 操作 │ - node_id         | panel_website  │
│                                   │-------------------------------------------------------│ - tunnel/source   | last_synced    │
│                                   │ 正常 | a.com  | hk-main | mc-web | 开 | 已同步      │ - website_alias   | last_error_msg │
│                                   │ 待同步| b.com | sg-aio  | npm    | 关 | 排队中      │ - primary_domain  | 手动覆盖状态   │
│                                   │ 异常 | c.com  | cf-edge | api    | 开 | 失败        │ - domains_json    |                │
│                                   │ ...                                                   ├───────────────────────────────────┤
│                                   │                                                       │ HTTPS / 证书      | 代理预览        │
│                                   │                                                       │ - https_enabled   | proxy_target    │
│                                   │                                                       │ - ssl_cert_ref    | https_port      │
│                                   │                                                       │ - 证书来源        | 主域名访问预览  │
│                                   │                                                       ├───────────────────────────────────┤
│                                   │                                                       │ 代理与缓存        |                │
│                                   │                                                       │ - proxy_enabled   |                │
│                                   │                                                       │ - cache_enabled   |                │
│                                   │                                                       │ - http_config     |                │
│                                   │                                                       ├───────────────────────────────────┤
│                                   │                                                       │ 高级覆盖（折叠）                  │
│                                   │                                                       │ - manual_override 摘要            │
│                                   │                                                       │ - 冲突处理策略                    │
│                                   │                                                       │ - runtime_key(只读)               │
│                                   │                                                       ├───────────────────────────────────┤
│                                   │                                                       │ [取消][仅保存映射][保存并创建任务]│

```

### 5.3 关键说明

- `domains_json` 在线框里必须表现成结构化域名区域，而不是 raw JSON 文本框。
- `proxy_target` 默认是预览，不建议首屏直接开放自由输入。
- `同步摘要` 区必须明确显示 `panel_website_id` 和最近错误，否则很难排查 1Panel 漂移。
- 当处于手动覆盖状态时，抽屉头部需要明显的黄色/红色提示条。

## 6. Frame D — 设置页卡片布局

### 6.1 目标

设置页不使用抽屉，而是独立全页。重点是：

- 卡片顺序稳定
- 阈值按钮清晰
- 凭据状态可读
- 危险操作隔离
- 固定保存条永远可见

│ - 设置                            ├────────────────────────────────────────────────────────────────────┤

### 6.3 关键说明

- 设置页不应该出现“超长滚动纯表单 + 零结构”。
- 危险操作卡片必须和普通保存彻底隔离。
- 凭据子卡应优先展示状态和错误，而不是展示 secret 内容。
- `固定保存条` 是实现时必须保留的结构，不是可选优化项。

## 7. 线框与前端组件边界的对应

### 7.1 组件拆分建议

| 线框区域 | 建议组件 |
|---|---|
| 页面壳 | `AppShell` |
| 页面标题区 | `PageHeader` |
| 列表筛选条 | `FilterBar` |
| 状态表格 | `ResourceTable` |
| 右侧抽屉 | `ResourceDrawerShell` |
| 抽屉中的只读摘要 | `ReadonlySummaryPanel` |
| 折叠高级区 | `AdvancedSection` |
| 固定底部按钮条 | `StickyActionBar` |
| 设置页卡片 | `SettingsCard` / `CredentialCard` / `DangerZoneCard` |

### 7.2 为什么先画这 4 张线框

因为这 4 张决定了：

- 列表页与抽屉的组合方式
- 复杂表单是否需要双栏布局
- 固定底部操作栏是否作为通用组件抽出
- 只读摘要区是否作为统一模式复用

也就是说，后面即使继续扩展仪表盘、日志详情、任务详情，这套线框骨架也不会浪费。

## 9. 结论

- 列表区怎么摆
- 抽屉怎么切块

- 固定按钮条放哪
- 设置页卡片如何分层

下一步如果继续推进，最合适的是：

1. 基于这份线框稿拆前端组件稿
2. 把字段映射到 DTO / API 请求体
3. 再进入页面实现顺序设计
