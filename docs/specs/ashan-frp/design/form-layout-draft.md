# Ashan FRP 资源表单布局稿（字段顺序 / 抽屉分区 / 按钮与状态反馈）

> 适用范围：`ashan-frp` 管理台中的资源创建 / 编辑表单与设置页。
> 目标：把节点、隧道、网站映射、设置等关键表单推进到“可以直接照着做 UI”的粒度。
> 约束：本文只定义目标布局、字段顺序、分区方式、只读/可编辑边界、按钮和异步反馈；不引入未验证的私有 API 细节。
> 当前状态说明：仓库当前前端仍是骨架态，本文描述的是 **目标设计**，不是现有实现复述。
> 配套文档：`architecture.md`、`frontend-ui.md`、`backend-schema.md`、`docker-to-1panel-association.md`、`frpc-runtime.md`。

---

## 1. 设计目标

这份稿子的作用不是讨论“要不要有这个页面”，而是把现有 Ashan FRP 设计继续往前推一步：

- 哪些字段应该出现在表单里。
- 这些字段应该按什么顺序摆。
- 哪些放基础区，哪些放高级区。
- 哪些字段允许编辑，哪些只读展示。
- 用户点“保存”后，页面应该给什么反馈。

核心设计原则：

1. **抽屉优先，不堆大弹窗**
   - 节点、隧道、网站映射这类长表单，优先右侧抽屉。
2. **基础信息先录，运行事实后看**
   - 可编辑字段放前面。
   - 观测态、错误态、快照、hash、远端 ID 一律只读靠后。
3. **异步动作必须显式反馈**
   - 保存动作如果会触发 job，必须提示“已保存 / 已排队 / 执行中”。
4. **业务字段可读，技术字段降噪**
   - 不把 `desired_hash`、`observed_hash`、`runtime_key` 这类内部字段直接丢到第一屏。
5. **危险区独立**
   - 删除、归档、强制覆盖、吊销凭据绝不和“保存”放一排。

## 2. 全局布局规则

### 2.1 抽屉宽度建议

| 资源 | 建议宽度 | 说明 |
|---|---:|---|
| 节点 | 720px | 中等复杂度，适合左右两列 + 底部固定按钮 |
| 隧道 | 960px | 需要配置定义 + 运行摘要 + 差异提示 |
| 网站映射 | 960px / 全屏 | 绑定、证书、代理、覆盖信息都较多 |
| 设置页 | 独立页面 | 不用抽屉，采用卡片分区 + 固定保存条 |

### 2.2 表单统一骨架

所有资源表单都统一为四层结构：

1. **顶部**
   - 标题
   - 一句话说明
   - 当前资源状态标签（编辑态时）
2. **中部主表单**
   - 按 3~5 个逻辑分区排列
3. **右侧摘要 / 预览区**（仅中大型表单）
   - 状态、预览、差异、最近结果
4. **底部固定操作栏**
   - 取消
   - 保存
   - 保存并触发动作（如排队应用）

### 2.3 字段显示层级

| 层级 | 处理方式 |
|---|---|
| 用户必须填写 | 基础区，首屏可见 |
| 用户偶尔会改 | 高级区，默认折叠 |
| 系统自动生成 | 只读预览，不让用户直接改 |
| 远端返回 / 运行事实 | 详情摘要区，只读 |
| 内部技术字段 | 不出现在主表单，只在调试视图或日志中显示 |

### 2.4 按钮统一规则

按钮顺序固定：

- 左侧：次要操作（测试连接、预览、复制）
- 右侧：`取消` → `保存` → `保存并应用/排队`（如果存在）
- 危险操作：单独放在危险区，不进底部主按钮组

### 2.5 保存后的反馈

| 场景 | 反馈 |
|---|---|
| 只改本地意图，不触发远端动作 | `已保存` |
| 保存并创建 job | `已保存，已加入任务队列` |
| 保存后立即进入执行 | `已保存，正在执行` |
| 需要等待上游返回 | `已提交，等待同步结果` |
| 验证失败 | 表单内联错误 + 顶部失败提示 |

## 3. 节点表单布局稿

### 3.1 页面目标

节点表单的核心不是录一堆健康信息，而是定义“这个系统应该连接哪个上游 / 哪个目标节点”。

所以：
- **连接定义是可编辑的**。
- **健康状态是只读观测结果**。

### 3.2 第一屏布局

```text
┌──────────────────────────────────────────────┬──────────────────────────────┐
│ 基础接入                                     │ 运行摘要（只读）             │
│ - 显示名称                                   │ - 当前状态                   │
│ - provider                                   │ - health_status              │
│ - node_type                                  │ - last_seen_at               │
│ - endpoint_url                               │ - last_success_at            │
│ - region                                     │ - last_error_message         │
│ - status(启用/停用)                          │                              │
└──────────────────────────────────────────────┴──────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────────┐
│ 高级标识（默认折叠）                                                        │
│ - canonical_name                                                            │
│ - external_id（编辑态只读）                                                 │
│ - metadata_json（如后续做 key-value editor，则放这里）                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 分区设计

#### 分区 A：基础接入
建议字段顺序：
1. `display_name`
2. `provider`
3. `node_type`
4. `endpoint_url`
5. `region`
6. `status`

#### 分区 B：运行摘要（只读）
编辑态展示：
1. `health_status`
2. `last_seen_at`
3. `last_success_at`
4. `last_error_code`
5. `last_error_message`

#### 分区 C：高级标识（默认折叠）
1. `canonical_name`
2. `external_id`（只读）
3. `metadata_json`

### 3.4 字段顺序建议

```text
field_order = [
  display_name,
  provider,
  node_type,
  endpoint_url,
  region,
  status,
  canonical_name,
  external_id,
  metadata_json,
]
```

### 3.5 不应出现在节点主表单第一屏的字段

- `account_id`
- `created_at`
- `updated_at`
- `archived_at`
- 原始快照内容
- 审计日志全文

这些应该去详情页、日志页或调试视图。

## 4. 隧道表单布局稿

### 4.1 页面目标

隧道表单定义的是“本地服务如何映射到远端”，因此第一屏必须让用户快速完成：

- 选节点
- 定义隧道名
- 录本地地址
- 录远端暴露方式
- 决定是否启用

运行态、差异、手动覆盖属于第二层信息。

### 4.2 抽屉规格

- 宽度：`960px`
- 结构：左侧主表单 + 右侧只读摘要

### 4.3 第一屏布局

```text
┌──────────────────────────────────────────────┬──────────────────────────────┐
│ 基础定义                                     │ 运行摘要（只读）             │
│ - 节点                                       │ - actual_state               │
│ - 隧道名                                     │ - state_reason               │
│ - tunnel_type                                │ - last_applied_at            │
│ - desired_state                              │ - last_error_message         │
│                                              │ - 手动覆盖状态               │
├──────────────────────────────────────────────┼──────────────────────────────┤
│ 本地目标                                     │ 预览 / 差异                  │
│ - local_ip                                   │ - canonical_key 预览         │
│ - local_port                                 │ - 域名 / 端口预览            │
│                                              │ - desired vs observed 提示   │
├──────────────────────────────────────────────┼──────────────────────────────┤
│ 远端暴露                                     │                              │
│ - remote_port                                │                              │
│ - dns_domain_cname                           │                              │
│ - dns_proxied                                │                              │
└──────────────────────────────────────────────┴──────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────────┐
│ 高级区（默认折叠）                                                          │
│ - external_id（只读）                                                       │
│ - manual_override_json（只读摘要，不直接编辑 raw json）                     │
│ - runtime_key（只读）                                                       │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.4 分区设计

#### 分区 A：基础定义
1. `node_id`
2. `name`
3. `tunnel_type`
4. `desired_state`

#### 分区 B：本地目标
1. `local_ip`
2. `local_port`

#### 分区 C：远端暴露
1. `remote_port`
2. `dns_domain_cname`
3. `dns_proxied`

#### 分区 D：运行摘要（只读）
1. `actual_state`
2. `state_reason`
3. `last_applied_at`
4. `last_error_code`
5. `last_error_message`

#### 分区 E：高级区（默认折叠）
1. `external_id`
2. `manual_override_json`（摘要显示）
3. `runtime_key`

### 4.5 字段顺序建议

```text
field_order = [
  node_id,
  name,
  tunnel_type,
  desired_state,
  local_ip,
  local_port,
  remote_port,
  dns_domain_cname,
  dns_proxied,
  external_id,
  manual_override_json,
  runtime_key,
]
```

### 4.6 表单动作建议

底部按钮：
- `取消`
- `仅保存`
- `保存并排队应用`

如果编辑的是已存在隧道，可在右上角更多菜单里放：
- 复制
- 归档
- 查看差异

### 4.7 不应直接暴露给用户编辑的字段

- `desired_hash`
- `observed_hash`
- `last_applied_snapshot_id`
- `account_id`

这些都是同步引擎内部字段，不属于业务表单输入。

## 5. 网站映射表单布局稿

### 5.1 页面目标

网站映射是 Ashan FRP 里最复杂的资源表单之一，因为它同时涉及：

- 绑定来源（隧道 / 容器）
- 域名
- HTTPS
- 代理目标
- 1Panel 站点对象
- 手动覆盖

因此它不适合小弹窗，应该是**复杂映射抽屉**或全屏抽屉。

### 5.2 抽屉规格

- 默认：`960px`
- 若支持更多高级代理配置：可升级为全屏抽屉

### 5.3 第一屏布局

```text
┌──────────────────────────────────────────────┬──────────────────────────────┐
│ 基础绑定                                     │ 同步摘要（只读）             │
│ - source_kind                                │ - status                     │
│ - 节点                                       │ - panel_website_id           │
│ - 隧道 / source_external_id                  │ - last_synced_at             │
│ - website_alias                              │ - last_error_message         │
│ - primary_domain                             │ - 手动覆盖状态               │
│ - domains_json                               │                              │
├──────────────────────────────────────────────┼──────────────────────────────┤
│ HTTPS / 证书                                 │ 代理预览                     │
│ - https_enabled                              │ - proxy_target               │
│ - ssl_certificate_ref                        │ - https_port                 │
│ - 证书来源（如已有证书/自动申请）            │ - 主域名访问预览             │
├──────────────────────────────────────────────┼──────────────────────────────┤
│ 代理与缓存                                   │                              │
│ - proxy_enabled                              │                              │
│ - proxy_cache_enabled                        │                              │
│ - http_config（高级）                        │                              │
└──────────────────────────────────────────────┴──────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────────┐
│ 高级覆盖（默认折叠）                                                        │
│ - manual_override_json 摘要                                                  │
│ - conflict strategy                                                          │
│ - runtime_key（只读）                                                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 5.4 分区设计

#### 分区 A：基础绑定
1. `source_kind`
2. `node_id`
3. `tunnel_id` 或 `source_external_id`
4. `website_alias`
5. `primary_domain`
6. `domains_json`

> `domains_json` 的前端不应直接是原始 JSON 文本框。应使用“主域名 + 多个备用域名输入项”的结构化控件，最终再转成 JSON。

#### 分区 B：HTTPS / 证书
1. `https_enabled`
2. `ssl_certificate_ref`
3. 证书来源（UI 字段，可映射到 `http_config` 或后端 payload）
4. `https_port`（只读或高级显示，不建议首屏让用户乱改）

#### 分区 C：代理与缓存
1. `proxy_enabled`
2. `proxy_cache_enabled`
3. `proxy_target`（优先只读预览；只有 `source_kind = custom` 时才允许编辑）
4. `http_config`（高级展开区）

#### 分区 D：同步摘要（只读）
1. `status`
2. `panel_website_id`
3. `last_synced_at`
4. `last_error_code`
5. `last_error_message`

#### 分区 E：高级覆盖（默认折叠）
1. `manual_override_json` 摘要
2. 冲突处理策略（UI 逻辑字段）
3. `runtime_key`

### 5.5 字段顺序建议

```text
field_order = [
  source_kind,
  node_id,
  tunnel_id,
  source_external_id,
  website_alias,
  primary_domain,
  domains_json,
  https_enabled,
  ssl_certificate_ref,
  https_port,
  proxy_enabled,
  proxy_cache_enabled,
  proxy_target,
  http_config,
  manual_override_json,
  status,
  panel_website_id,
  last_synced_at,
  runtime_key,
]
```

### 5.6 表单动作建议

底部按钮：
- `取消`
- `仅保存映射`
- `保存并创建同步任务`

编辑态右上角更多菜单：
- 刷新同步
- 复制映射
- 归档
- 接受远端为事实 / 恢复本地定义（仅手动覆盖状态显示）

### 5.7 不建议在第一版主表单直接出现的内容

- 原始 1Panel API 返回体
- `last_remote_hash`
- 全量 `manual_override_json`
- 低层证书申请调试参数

这些应进调试视图或日志详情，而不是业务操作首屏。

## 6. 设置页布局稿

### 6.1 页面目标

设置页是“系统行为配置页”，不是单一大表单。

应采用：
- 多卡片分区
- 每块卡片自解释
- 固定刻度按钮
- 独立危险区

### 6.2 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 通用控制卡片                                                │
├──────────────────────────────────────────────────────────────┤
│ 同步策略卡片                                                │
├──────────────────────────────────────────────────────────────┤
│ 队列 / 重试卡片                                             │
├──────────────────────────────────────────────────────────────┤
│ FRPC Runtime 卡片                                           │
├──────────────────────────────────────────────────────────────┤
│ 上游凭据与授权卡片（ChmlFrp / 1Panel / Cloudflare）         │
├──────────────────────────────────────────────────────────────┤
│ 危险操作卡片                                                │
└──────────────────────────────────────────────────────────────┘
[底部固定保存条：取消 | 保存全部]
```

### 6.3 卡片顺序与字段建议

#### 卡片 A：通用控制
建议顺序：
1. 默认数据刷新显示方式
2. 日志默认显示条数（50 / 100 / 200）
3. 数据保留期（7 天 / 30 天 / 90 天 / 永久）

#### 卡片 B：同步策略
建议顺序：
1. 健康检查间隔（30 秒 / 1 分钟 / 3 分钟 / 5 分钟 / 10 分钟）
2. 同步轮询间隔（5 秒 / 10 秒 / 30 秒 / 1 分钟）
3. 差异处理策略
4. 手动覆盖优先级策略

#### 卡片 C：队列 / 重试
建议顺序：
1. 最大重试次数
2. 重试退避（15 秒 / 30 秒 / 1 分钟 / 5 分钟 / 15 分钟）
3. stalled job 自动处理策略
4. 归档保留策略

#### 卡片 D：FRPC Runtime
根据 `frpc-runtime.md`，建议顺序：
1. `frpc_enabled`
2. `frpc_binary_source`
3. `frpc_binary_version`
4. `frpc_log_level`
5. `frpc_healthcheck_interval`
6. `frpc_restart_backoff`
7. 自动恢复策略
8. 切换节点策略

#### 卡片 E：上游凭据与授权
每个 provider 一张子卡：
- ChmlFrp
- 1Panel
- Cloudflare

每张子卡统一顺序：
1. 凭据名称 / provider
2. 当前状态
3. 最近验证时间
4. 最近错误摘要
5. 操作按钮：重新验证 / 重新授权 / 旋转 / 吊销

> 密钥明文不在页面展示，只显示掩码摘要和状态。

#### 卡片 F：危险操作
建议顺序：
1. 重置本地缓存
2. 清空已完成作业归档
3. 吊销全部上游授权
4. 恢复默认设置

### 6.4 设置页按钮规则

- 页面底部固定：`取消`、`保存全部`
- 危险操作不走主保存按钮，而是卡片内独立危险按钮
- 有未保存变更时，右上角和底部都要给提示

这些不是资源创建表单，但同样属于高频“表单输入”。字段顺序必须固定，避免每页筛选器风格混乱。

## 8. 字段显示与只读边界

### 8.1 应只读展示的字段

| 资源 | 只读字段 |
|---|---|
| 节点 | `health_status`、`last_seen_at`、`last_success_at`、`last_error_*`、`external_id` |
| 隧道 | `actual_state`、`state_reason`、`last_applied_at`、`last_error_*`、`runtime_key` |
| 网站映射 | `status`、`panel_website_id`、`last_synced_at`、`last_error_*`、`runtime_key` |
| 设置 | 最近验证时间、最近错误摘要、凭据状态 |

### 8.2 不应直接做 raw JSON 输入的字段

- `domains_json`
- `manual_override_json`
- `metadata_json`
- `http_config`

第一版 UI 应尽量用结构化控件或只读摘要；只有高级调试模式才允许 raw JSON 编辑。
