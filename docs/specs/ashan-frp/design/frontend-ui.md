# 前端页面布局 / 交互设计

> 适用范围：`ashan-frp` 前端管理台。
> 约束：只描述页面地图、布局、交互、状态与控件规则，不包含实现代码。
> 说明：当前运行态 UI 由 Go 二进制通过 `/ui/` 提供；**浏览器里真正运行的是 HTML / CSS / JavaScript**，Go 只负责提供静态资源和 API。当前实现已经按这一路线落地，不再依赖独立前端服务器。本文与 `docs/specs/ashan-frp/design/backend-schema.md` 配套，前端页面以该 schema 中的 `nodes`、`tunnels`、`website_mappings`、`jobs`、`settings`、`snapshots`、`job_events`、`audit_log` 为数据基础。资源创建 / 编辑的字段顺序与抽屉分区细节请另见 `form-layout-draft.md`。接口合同与请求体映射请另见 `api-payload-mapping.md`。

## 1. 设计目标

这套前端不是“把所有表格堆在一起”，而是让运维人员在最短时间内回答四个问题：

1. 现在稳不稳？
2. 哪个资源有问题？
3. 问题是配置、同步、任务还是外部依赖？
4. 我点下去之后，系统会不会立刻做事，还是只是排队？

因此前端设计遵循以下原则：

- 先看全局健康，再看具体资源。
- 所有会影响阈值、周期、保留期、重试策略的设置，统一使用固定刻度按钮或分段控件，不使用连续滑块。
- 所有异步动作都要有明确的“已提交 / 排队中 / 执行中 / 成功 / 失败”反馈。
- 高风险动作必须显式确认，不允许“点一下就永久生效而页面没提示”。
- 详情以抽屉为主，弹窗只用于短表单和确认。
- 空状态不是死胡同，必须给出下一步动作。

## 2. 全局信息架构

### 2.1 导航分组

建议使用左侧侧边栏 + 顶部工具栏的经典后台布局，导航分组如下：

- 概览
  - 仪表盘
- 资源
  - 节点列表
  - 隧道列表
  - 网站映射
- 运营
  - 任务队列
  - 日志
- 系统
  - 设置

系统页之外还应保留独立的登录页、会话过期页、403/404 页，用于异常入口和权限场景。

### 2.2 页面地图 / 路由

| 导航名 | 路由 | 主要数据源 | 页面目的 |
|---|---|---|---|
| 仪表盘 | `/dashboard` | `nodes`、`tunnels`、`website_mappings`、`jobs`、`sync_state` | 一屏掌握系统健康与待处理问题 |
| 节点列表 | `/nodes` | `nodes`、`snapshots`、`audit_log` | 管理上游节点、宿主与健康状态 |
| 节点详情 | `/nodes/:id` | `nodes`、`snapshots`、`job_events` | 查看单个节点的配置、历史与依赖 |
| 隧道列表 | `/tunnels` | `tunnels`、`sync_state`、`snapshots`、`job_events` | 管理固定隧道与运行态差异 |
| 隧道详情 | `/tunnels/:id` | `tunnels`、`sync_state`、`snapshots` | 查看定义、观测、冲突与最近执行 |
| 网站映射 | `/website-mappings` | `website_mappings`、`snapshots`、`audit_log` | 管理 1Panel 网站对象与域名映射 |
| 网站映射详情 | `/website-mappings/:id` | `website_mappings`、`snapshots`、`job_events` | 查看域名、HTTPS、代理与覆盖痕迹 |
| 任务队列 | `/jobs` | `jobs`、`job_events` | 观察排队、重试、失败与锁定情况 |
| 任务详情 | `/jobs/:id` | `jobs`、`job_events` | 看单个作业的事件时间线和结果 |
| 设置 | `/settings` | `settings`、`upstream_credentials`、`audit_log` | 管理频率、阈值、通知与凭据 |
| 日志 | `/logs` | `job_events`、`audit_log`、`snapshots` | 查看运行日志、审计记录与原始快照 |

### 2.3 顶部工具栏

顶部工具栏固定展示以下元素：

- 当前页面标题与简短说明。
- 全局搜索入口：支持按名称、域名、节点名、外部 ID 模糊查找。
- 实时状态指示：SSE 已连接 / 正在回退 polling / 最近刷新时间。
- 手动刷新按钮：对当前页立即拉取最新数据。
- 用户入口：账号信息、退出登录。

在后台管理场景里，顶部工具栏不是装饰，而是“当前数据是不是新鲜”的可视化入口。

## 3. 全局布局规范

### 3.1 桌面端结构

- 左侧侧边栏：240px 左右，支持收起。
- 主内容区：默认全宽，表格页允许铺满窗口。
- 页面头部：标题、说明、主按钮、次级操作。
- 列表页：头部下方固定筛选条，下面是表格或卡片网格。
- 详情页：左侧主内容，右侧摘要信息或时间线。

### 3.2 移动端结构

- 左侧导航收起为抽屉。
- 表格自动降级为卡片列表。
- 详情优先使用全屏抽屉而不是窄弹窗。
- 主操作按钮始终保留在屏幕底部可触达区域。

### 3.3 状态语义统一

所有页面复用同一套状态语义：

- 绿色：正常、已同步、已启用、成功。
- 黄色：警告、待处理、存在差异、需要关注。
- 红色：失败、冲突、不可用、需要人工介入。
- 灰色：未知、未启用、归档、无数据。
- 蓝色：进行中、排队中、信息态。

状态标签必须同时有颜色和文字，不允许只靠颜色表达。

### 3.4 详情打开方式

- 列表中的行点击默认打开详情抽屉。
- 若内容已经有独立路由，则详情抽屉应提供“在新页打开”入口。
- 只有需要长表单编辑时才进入独立编辑页或全屏抽屉。

## 4. 仪表盘设计

仪表盘是首页，也是值班页。目标不是展示花哨图表，而是让人快速决定“要不要立刻处理”。

### 4.1 卡片布局

建议 2 行 × 3 列卡片布局，卡片统一包含：

- 主数字：最重要的状态值。
- 次级分布：健康 / 警告 / 失败 / 待处理等。
- 最近更新时间：最后一次同步、执行或刷新时间。
- 主操作：进入对应列表页或触发常见动作。

### 4.2 建议的卡片

1. 节点健康
   - 展示：总节点数、在线、降级、离线、封禁数。
   - 关注点：最近一次心跳时间、最近失败原因。
   - 主操作：查看节点列表。

2. 隧道状态
   - 展示：已启用、待应用、冲突、手动覆盖、失败。
   - 关注点：当前是否存在“同一业务不同实例”的漂移。
   - 主操作：查看隧道列表。

3. 网站映射
   - 展示：已同步、待同步、HTTPS 异常、手动覆盖。
   - 关注点：域名是否已经指向正确目标。
   - 主操作：查看网站映射。

4. 任务队列
   - 展示：等待中、运行中、失败、卡住、已完成。
   - 关注点：最老的待执行任务、当前锁定者。
   - 主操作：查看任务队列。

5. 异常与告警
   - 展示：当前未关闭的严重/警告事件数。
   - 关注点：最新一条错误摘要。
   - 主操作：查看日志。

6. 同步新鲜度
   - 展示：最近成功同步时间、下一次计划检查时间、数据是否过期。
   - 关注点：是否已经超过预期刷新窗口。
   - 主操作：手动刷新当前视图。

### 4.3 仪表盘下半区

卡片下面建议保留一个“最近动态”区域，显示最近几条 `job_events` / `audit_log` 事件，方便运维人员不跳页就能看见最新动作。

## 5. 页面设计

### 5.1 节点列表页

#### 页面目标

节点页是整个系统的资源底座。这里要回答的是：哪些节点存在、哪些节点健康、哪些节点已经不值得再自动操作。

#### 主区域

- 顶部筛选条：搜索框、状态筛选、provider 筛选、归档开关、刷新按钮。
- 表格列建议：
  - 状态
  - 节点名 / 显示名
  - provider
  - endpoint / 区域
  - 最后心跳
  - 最后成功时间
  - 依赖数量
  - 操作

#### 行内状态

- 在线 / 降级 / 离线 / 封禁 / 归档。
- 若节点存在多个下游资源，行内要显示依赖数，避免误删。
- 若最近失败，显示失败原因摘要，不要只显示红点。

#### 行内操作

- 查看详情
- 立即检查
- 编辑
- 归档
- 查看相关日志

#### 详情抽屉

建议分成 4 个分区：

- 概览：基础信息、provider、endpoint、状态。
- 资源关系：绑定的隧道、网站映射数。
- 历史：最近 `snapshots`、最近 `job_events`。
- 审计：最近 `audit_log` 记录。

#### 空状态

- 标题：还没有节点
- 说明：先添加一个节点，系统才能做健康检查和自动同步。
- 主按钮：添加节点
- 次按钮：查看接入说明

### 5.2 隧道列表页

#### 页面目标

隧道页展示“业务定义”和“运行事实”的差异。用户要能一眼看出：这个隧道是否还指向正确的位置，是否存在冲突或漂移。

#### 主区域

- 顶部筛选条：名称搜索、状态筛选、节点筛选、冲突筛选、手动覆盖筛选。
- 表格列建议：
  - 状态
  - 隧道名
  - 绑定节点
  - 本地地址 / 端口
  - 远端端口 / 域名
  - 期望状态
  - 实际状态
  - 最后应用时间
  - 操作

#### 重要视觉提示

- 期望态与观测态必须分别展示。
- 如果二者不同，用“差异”标签，而不是只靠颜色。
- 如果存在手动覆盖，必须显式标注“手动覆盖中”。

#### 行内操作

- 编辑
- 启用 / 停用
- 立即应用
- 复制
- 归档
- 查看差异

#### 详情抽屉

建议包含：

- 定义摘要：节点、本地地址、协议、域名。
- 运行摘要：最近一次 `sync_state`、最近一次成功应用。
- 差异视图：期望值 vs 观测值。
- 最近作业：关联的 `jobs` 与 `job_events`。

#### 空状态

- 标题：还没有隧道
- 说明：创建隧道后，系统才能把本地服务映射到远端。
- 主按钮：新建隧道

### 5.3 网站映射页

#### 页面目标

网站映射页用于管理 1Panel 站点对象、域名、HTTPS、代理以及人工覆盖痕迹。这里要让用户能迅速判断：站点是否已经正确指向隧道，证书和代理有没有异常。

#### 主区域

- 顶部筛选条：域名搜索、节点筛选、HTTPS 状态、同步状态、归档开关。
- 表格列建议：
  - 状态
  - 主域名
  - 备用域名数
  - 绑定节点
  - 绑定隧道
  - HTTPS
  - 代理状态
  - 最近同步
  - 操作

#### 页面重点

- 域名与站点对象必须一一对应到可追踪的映射关系。
- `panel_website_id`、`primary_domain`、`domains_json`、`ssl_certificate_ref` 之类字段应在详情里展示为可读信息，而不是直接暴露成技术噪声。
- 若存在手动覆盖，显示覆盖来源和最后一次修改人。

#### 行内操作

- 编辑映射
- 启用 / 停用 HTTPS
- 刷新同步
- 复制映射
- 归档

#### 表单布局

网站映射的表单建议用分段抽屉：

1. 基础绑定
   - 节点
   - 隧道
   - 主域名
   - 备用域名

2. HTTPS / 证书
   - HTTPS 模式
   - 证书引用
   - 证书来源

3. 代理与缓存
   - 代理开关
   - 缓存开关
   - 目标地址预览

4. 高级覆盖
   - 手动覆盖说明
   - 同步冲突处理策略

该分区的更细字段顺序与抽屉结构，统一以 `form-layout-draft.md` 为准。

#### 空状态

- 标题：还没有网站映射
- 说明：先把节点和隧道连起来，再创建域名映射。
- 主按钮：新建映射

### 5.4 任务队列页

#### 页面目标

任务队列页是系统的执行中枢。它要回答：任务现在排到哪了、为什么失败、是谁锁住了、重试会不会再次失败。

#### 主区域

- 顶部筛选条：状态、job type、目标类型、目标 ID、锁定状态、时间范围。
- 表格列建议：
  - 状态
  - 作业类型
  - 目标对象
  - 优先级
  - 运行时间 / 计划时间
  - 尝试次数
  - 当前锁定者
  - 最近结果
  - 操作

#### 行内状态

- queued / running / success / failed / cancelled / stalled。
- stalled 必须高亮，因为它通常意味着锁异常或 worker 异常。
- failed 需要显示失败摘要和重试次数。

#### 行内操作

- 查看详情
- 立即重试
- 取消
- 立即执行
- 解锁卡住任务
- 查看日志

#### 详情抽屉

- 作业摘要：目标对象、创建人、idempotency key。
- 事件时间线：`job_events` 按时间顺序展示。
- 结果摘要：最终状态、错误码、错误信息。
- 原始负载：折叠展示，默认不展开。

#### 空状态

- 标题：当前没有待执行任务
- 说明：当系统没有冲突、同步或重试需要时，这里会保持为空。
- 次按钮：刷新

### 5.5 设置页

#### 页面目标

设置页不应像一张长表单，而应是“少量大块配置卡片 + 清晰的阈值按钮组 + 危险区隔离”。

#### 建议分区

- 通用
- 同步策略
- 频率与阈值
- 通知与告警
- 凭据与集成
- 危险操作

#### 阈值按钮规则

所有会参与自动化决策的数值都必须用固定刻度按钮或分段控件表达，例如：

- 健康检查间隔：30 秒 / 1 分钟 / 3 分钟 / 5 分钟 / 10 分钟
- 队列轮询间隔：5 秒 / 10 秒 / 30 秒 / 1 分钟
- 重试退避：15 秒 / 30 秒 / 1 分钟 / 5 分钟 / 15 分钟
- 日志默认显示条数：50 / 100 / 200
- 数据保留期：7 天 / 30 天 / 90 天 / 永久

不要用连续滑块，因为滑块会掩盖边界值，用户也很难在审计和协作时准确复述设置。

如果必须支持自由输入，只能放在“高级”折叠区，并且要在旁边明确显示推荐档位与生效范围。

#### 凭据与集成

- 仅展示掩码后的凭据摘要。
- 提供“重新验证”“旋转”“重新授权”按钮。
- 每个凭据卡片都要显示最后验证时间和最近错误。
- 不在页面上暴露明文 secret。

#### 危险操作

- 重置所有本地缓存
- 吊销上游凭据
- 清空已完成作业归档
- 恢复默认设置

这些操作必须与普通保存按钮分区放置，不能混在同一行。

#### 设置页底部

- 固定保存条：保存 / 取消 / 放弃更改
- 未保存状态提示：右上角显示“有未保存更改”

### 5.6 日志页

#### 页面目标

日志页是排障入口，重点是“快筛选、快定位、快回看”。

#### 建议使用标签页

- 作业日志
- 审计日志
- 同步轨迹
- 原始快照

#### 主区域

- 顶部筛选条：来源、等级、目标类型、目标 ID、时间范围、关键词。
- 主体视图：时间线表格或日志列表。
- 右侧详情：查看单条日志的完整上下文。

#### 直播模式

当用户打开“最新日志”或“尾随模式”时：

- 优先使用 SSE。
- SSE 断开后自动回退到 polling。
- 页面必须明确展示“正在实时接收 / 正在轮询 / 连接已断开”。
- 如果用户手动滚动离开底部，自动暂停跟随，避免打断阅读。

#### 日志详情

建议展示：

- 时间戳
- 来源类型
- 目标对象
- 级别
- 简要摘要
- 关联作业 / 关联审计记录
- 原始 payload

#### 空状态

- 如果没有数据：提示当前筛选范围内没有日志。
- 如果是筛选过严：提供“一键清空筛选条件”。
- 如果加载失败：显示错误 banner + 重试按钮。

## 6. 异步交互规范

### 6.1 乐观更新

适合乐观更新的动作：

- 启用 / 停用开关
- 标签或显示名修改
- 列表筛选条件
- 视图密度、排序、分页
- “记住当前过滤器”之类纯前端状态

不适合乐观更新的动作：

- 删除 / 归档
- 立即应用
- 解锁卡住作业
- 吊销凭据
- 改变会触发远端写入的配置

乐观更新时必须：

- 先显示“已提交”而不是假装完成。
- 失败时回滚并提示原因。
- 同时防止重复点击。

### 6.2 Polling 与 SSE

建议策略如下：

| 页面 | 默认更新方式 | 回退方式 |
|---|---|---|
| 仪表盘 | SSE / 低频 polling | 手动刷新 |
| 节点列表 | polling | 手动刷新 |
| 隧道列表 | polling | 手动刷新 |
| 网站映射 | polling | 手动刷新 |
| 任务队列 | SSE 优先 | polling |
| 日志 | SSE 尾随模式 | polling |
| 设置 | 进入页面时拉取 + 保存后刷新 | 手动刷新 |

通用要求：

- 页面右上角必须显示最后更新时间。
- 当数据可能过期时，要提示“数据已过期 / 正在重新同步”。
- 连接中断时不要静默失败，必须显示 banner。

### 6.3 错误 banner

错误展示分 3 层：

1. 全局 banner：认证失效、SSE 断开、后端不可用。
2. 页面 banner：当前页刷新失败、列表加载失败。
3. 行内错误：某个节点、隧道或作业自身失败。

规则：

- 全局 banner 固定在内容区顶部。
- 行内错误要带对象名和简短原因。
- 可以恢复的错误必须有“重试”按钮。

### 6.4 空状态

所有空状态统一模板：

- 图标或占位插画
- 一个简短标题
- 一句解释
- 一个主按钮
- 可选一个次按钮

每个页面至少要有一套合理的空状态文案，不能只显示“暂无数据”。

### 6.5 过期与脏数据提示

当列表与后端状态可能不同步时，要显式标记：

- “最后刷新：2 分钟前”
- “当前数据可能已过期”
- “正在应用中，请稍候”

这种提示比让用户手动猜测更重要。

## 7. 表单、抽屉与弹窗

### 7.1 抽屉优先

创建和编辑资源时，优先使用右侧抽屉而不是中央大弹窗，因为：

- 抽屉更适合长表单。
- 抽屉可以保留列表上下文。
- 抽屉更容易在移动端降级成全屏页。

建议宽度：

- 简单表单：520px 左右。
- 中等复杂度：720px 左右。
- 复杂映射表单：960px 左右或全屏抽屉。

### 7.2 表单布局

推荐的表单结构：

- 顶部：标题 + 简短说明。
- 中间：按逻辑分成 3~4 个分区。
- 右侧：可选帮助说明、状态摘要或实时预览。
- 底部：固定操作栏，始终可见。

具体到节点 / 隧道 / 网站映射 / 设置页的字段顺序和分区草图，统一下沉到 `form-layout-draft.md`，避免本文同时承载页面地图和字段级稿件。页面级 wireframe 另见 `wireframe-draft.md` 与 `wireframe-draft.excalidraw`。

复杂资源的表单建议使用“基础 / 高级”分层，默认只展开基础项。

### 7.3 关键按钮位置

- 保存：始终是正向主按钮，放在右下角。
- 取消：紧邻保存，但视觉权重更弱。
- 危险操作：不要和保存并排放在一起，放到独立危险区或更多菜单里。

### 7.4 确认弹窗

适用于以下动作：

- 删除节点 / 隧道 / 网站映射
- 吊销凭据
- 清空日志 / 清空归档
- 强制解锁 / 强制重试

确认弹窗必须包含：

- 标题
- 后果说明
- 受影响对象数量
- 若可行，列出最重要的依赖或回滚提醒
- 主按钮用危险色

对于不可逆动作，建议增加二次确认，例如输入资源名称。

## 8. 关键操作规范

### 8.1 删除与归档

- 先判断是否存在依赖。
- 若存在依赖，先展示影响范围，再允许确认。
- 删除成功前，不要在 UI 上直接消失；可以先标记为“正在删除”。

### 8.2 立即应用 / 立即同步

- 点击后立即进入排队状态。
- UI 显示“已提交，等待执行”。
- 成功后再更新实际状态。
- 失败时显示失败原因与重试入口。

### 8.3 重新验证凭据

- 先显示上次验证状态。
- 点击后进入异步校验流程。
- 若需要重新授权，跳转到明确的授权流程，不要留在原页静默失败。

### 8.4 批量操作

- 批量操作只允许在列表页使用。
- 必须显示选中数量与影响范围。
- 批量失败时要分项呈现，不要只给一个总失败提示。

## 9. 可访问性与基本体验

- 所有图标按钮必须有文字或 tooltip。
- 状态不能只靠颜色。
- 键盘支持：`Esc` 关闭抽屉/弹窗，`Enter` 提交，`Ctrl/Cmd + Enter` 保存长表单。
- 焦点状态要明显，不能被主题颜色吞掉。
- 表格密度默认以可读优先，不以极限压缩优先。
- 搜索框应支持键盘快速聚焦，常见约定是 `/` 或 `Ctrl/Cmd + K`。

## 10. 与后端 schema 的对应关系

前端页面与后端对象的建议对应如下：

- 仪表盘：聚合层，不直接编辑数据，只做汇总和跳转。
- 节点列表：对应 `nodes`，详情补充 `snapshots` 和 `audit_log`。
- 隧道列表：对应 `tunnels`，同时看 `sync_state`、`snapshots`、`job_events`。
- 网站映射：对应 `website_mappings`，详情里展示同步痕迹与审计记录。
- 任务队列：对应 `jobs`、`job_events`。
- 设置：对应 `settings`、`upstream_credentials`。
- 日志：对应 `job_events`、`audit_log`、`snapshots`。

核心要求是：前端术语面向业务，后端对象名只在详情和调试视图里出现。

## 11. 总结

这套前端设计的重点不是“多”，而是“清楚”：

- 页面少，但每个页面都能做决定。
- 指标少，但每个指标都能驱动操作。
- 控件少，但每个控件都能解释阈值。
- 异步多，但每个异步动作都有明确状态。

只要这四点成立，运维人员就能在仪表盘、资源页、队列页和日志页之间快速闭环，不需要靠猜。
